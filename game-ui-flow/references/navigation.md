# 导航与状态

适用于跨页面、弹窗、暂停、奖励和剧情流程。不要给单页文字修改强加路由工程。

## 建立必要的页面记录

对本次涉及的页面记录：用途、入口、主要动作、成功/取消出口、需要保留的选择、数据来源、滚动区、暂停责任。记录最小充分信息，已有可靠文档可以复用。页面标题相同不表示它们来自同一处。

返回上层与回首页可不同。来自结算的角色页、来自衣柜的角色页，都可以使用同一组件，返回上下文却不同。需要恢复列表筛选、滚动或焦点时存相应值；不机械保存无意义的瞬时状态。

确认退出、重试、新开一局等流程可以明确重置状态。不要为保持历史而回到已经失效的结果、已消费奖励或旧对局。

## 区分三种状态

- 持久进度：物品、奖励回执、已完成事件，服从现有事务。
- 本局状态：暂停原因、当前玩法与临时能力，服从游戏规则。
- 界面状态：浏览对象、页签、筛选、焦点和滚动，通常不应改变游戏权益。

一次打开详情不是购买，一次重绘不是领奖，离开设置也不自动等于继续游戏。渲染读取已确认状态，变更通过明确操作完成。恢复或重新打开页面不能重复执行副作用。

## 子弹窗

确定父页面与关闭责任，复用平台可靠的模态能力。网页中可参考 [WAI 模态弹窗模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)：
打开时焦点进入弹窗，键盘在弹窗内操作，有可见的关闭方式，关闭后回到合理触发点，背景不能继续接收操作。

点击遮罩是否关闭、取消是否丢弃草稿按任务决定；消费和破坏性操作不能由误触遮罩触发。普通选择弹窗不应要求长时间等待。结束演出、不可中断提交等有意的输入锁必须有明确的结束/错误出口，不能把该特殊规则套到所有弹窗。

父页面被替换时清理子弹窗、事件、动画及焦点引用。若触发点已经不存在，返回父页面的合理控件。浏览器返回与应用内返回的关系要按宿主处理，不为拦截退出随意污染浏览历史。

## 异步与生命周期

异步交易完成可以保存数据，但不应把已经离开的玩家拉回旧页面。用页面实例/请求标识核对显示归属；请求失败恢复可操作状态并保留用户仍需的输入。

区分暂停、恢复、显示暂停菜单。不要在嵌套设置的“返回”中调用有切换语义的暂停函数。页面退出后只移除自己创建的资源，避免破坏正在运行的其他控制器。
