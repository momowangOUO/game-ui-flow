# 布局、输入与语言

布局预算从实际内容区开始：浏览器工具栏、嵌入容器、安全区、横竖屏和软键盘会改变可用高度。复用项目视口入口；不要让每个页面各算一套屏高。

战斗 HUD 优先当前操作对象、角色/目标状态及即时决策，背景装饰不能吞掉关键标签。管理页需要比较和阅读，可以滚动。固定标题与关键操作、单一主体滚动区常有效，但不是所有页面的模板。小屏先减少空白和装饰，再调整分组，不靠极小字和不可点的按钮解决拥挤。

网格列数以完整名称和触控目标决定，长语言必要时增加行高。禁止横向溢出不等于禁止任何水平交互；用户看得见的横向选择器可用，但不应把主要出口藏在屏外。

按项目实际输入设计触摸、鼠标、键盘或手柄。不强迫触摸项目手柄优先；没有手柄支持时不宣称完成。触控区与视觉位置要一致，镜头震动与界面动画不能改碰撞/点击坐标。选中、聚焦、按下及不可用应可区分。拖动或滑动结束不能误触底层操作。

使用实际目标语言检查换行、文字方向、数字顺序、字体覆盖和控件顺序。RTL 不机械镜像美术或数值；内容顺序和操作方向根据语言与机制判断。缺译、截断和语义错误是不同问题。

概念图用于方向，真实组件负责适配、文字和输入。若用户要求先图像生成，再制作参考；否则按任务使用草图、组件或真实界面。不要把演示截图当作功能已实现或真机已验证。


## 图片的比例与裁切

图片默认保持素材的宽高比，范围包括头像、立绘、物品、奖励、背景、图标、宣传图，以及 Canvas 绘制和动效。容器形状可以变化，不代表里面的人物也要随之变形。完整展示使用等比容纳；需要填满时可等比覆盖并裁切，须保留脸、文字和其他关键内容。只看 CSS 的宽高或 `object-fit` 不够，核对素材本身、最终规则、父容器、transform 和实际运行画面。

头肩像可用经过校准的视窗裁切，普通图与表情图保持稳定的眼线、头部大小和构图；不能把固定裁切误做成改变图片宽高比。动效默认平移、旋转或等比缩放，只有明确的表现设计才能做非等比变形。

有意的九宫格面板、可平铺纹理或特定变形效果可以例外，但需记录具体素材、用途、允许变形的区域与理由，并验证不会带动人物、图标或文字变形。“填满空白”本身不是理由。不应以全局 `object-fit` 覆盖掩盖已有裁切和命中区域问题。

验收时对照素材原比例，检查窄屏、宽屏、横屏、预览、装备和状态切换；区分拉伸、裁切、留白与素材自带的透明边。自动尺寸检测不能替代逐张看脸和构图。

## 阅读内容的身份

剧情界面区分叙述、具名对白和玩家选项。使用数据中的说话人，不以当前立绘推定；通过姓名／叙述标记、分组与排版共同区分，不只换颜色。选项应在视觉上属于玩家操作，不能被包成角色说出的话。没有配角原画时，保留准确姓名，不借用另一人物的脸。长文本可滚动，推进与返回控件保持可达；按语言检查真实段落而非只有示例短句。
