# 验证与试用

选择与改动相关的真实路径，不为小修改重复全项目耗时测试。保留原始证据与构建版本，改动后旧截图不自动证明当前正确。

## 可观察的检查

- 从每种主要入口进入，确认操作对象正确，取消和返回抵达约定位置。
- 比较打开前后持久状态；纯浏览不扣款、不发奖、不改装备。
- 交易成功、失败、重复点击后数量和反馈一致，提交期间离开不抢回页面。
- 暂停中的设置/详情返回仍暂停；继续才推进游戏。
- 选卡、编辑、取消和确认后的画面与真实阶段一致，没有空白遮罩。
- 小屏、长文本、RTL及实际输入可完成主要动作。
- 图片按素材原比例展示；分别核对 DOM、背景和 Canvas、动效及最终覆盖样式。头像和表情切换不变形；有意拉伸逐项说明用途、范围和理由。
- 重复开关和切页后，没有残留弹窗、不断增加的监听器或动画任务。
- 概念图、源码检查、自动化运行、真机和用户审美反馈分别记录。

用屏幕录制/截图展示路径和布局，用状态断言检验交易/暂停。性能结论需测量，不凭截图或“感觉流畅”。

## 技能本身的试用

以下是测试请求，不是已经通过的记录：
1. 给出有完整数据却每页仅显示少量礼物的界面，请在不改经济规则下改善查找。
2. 给出暂停设置返回会恢复对局的代码，请定位原因并作最小修复。
3. 给出桌面战术游戏的机库、出战编队和装配界面，组织比较与返回路径；检查是否错误照搬手机三列礼物弹窗。
4. 仅要求检查标题文案，确认不会擅自重写路由或画面。

独立试用时给目标与原始材料，不提前告诉评估者预期答案。结构校验只说明技能文件有效；行为试用、实际项目验证与用户认可另记。发现问题修正具体指导，不增加没有证据的通用强制步骤。
