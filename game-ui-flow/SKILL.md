# 游戏界面流程

让玩家知道现在在哪、正在对什么操作、接下来会发生什么，以及怎样返回。先核实当前实现和玩家任务，再决定页面组织；现有问题不是重做全部界面的理由。

## 使用方式

盘点、规划、实现和审查都可使用，交付深度服从用户请求。只要求诊断时不改代码；获准修复时完成运行验证，不把设计说明当作成品。用户、项目和平台要求优先于这里的案例。

1. **找到真实界面。** 读取入口、最终运行代码、数据来源和已有验证；留意构建注入、旧定义被覆盖及不同状态走不同入口。查看实际画面，不把概念图或旧截图当成当前实现。
2. **按玩家任务分组。** 写清页面服务的决定：开始游玩、比较物品、选择目标、配置、消费、阅读还是查看结果。角色与衣服可以关联，但预览、购买、穿戴是不同动作。功能相关不代表必须挤在同一屏。
3. **选择合适的承载方式。** 高频且影响即时决策的信息留在当前界面；比较大量内容用列表或网格；短暂选择可用弹窗；长任务用页面。分页、滚动、筛选按内容规模和设备决定，不设通用列数或“所有页面禁止滚动”。
4. **约定状态与返回。** 明确页面和子弹窗由谁打开、关闭后去哪、保留哪些选择、是否暂停。不要用当前玩法阶段猜进入来源。浏览、取消和返回不应意外触发购买、领奖、装备或恢复游戏。确有这类产品规则时，提前让玩家知道。
5. **最小改动落实。** 复用已有页面壳、数据目录、事务、视口和输入系统；数据与画面区分，避免每页各自扣款或重新实现物品目录。不为整理流程引入无必要的框架。
6. **跑完整路径。** 从真实入口到结果再返回，检查对象、数量、角色和状态是否一致；用目标尺寸与语言验证；检查图片实际显示比例，头像、立绘、物品图默认等比缩放，不能用拉伸塞满容器。把源码推断、实际运行和真机结果分开报告。

## 协作与交付

本技能负责信息架构和操作连续性。文字任务可配合现有 clear-natural-writing；美术、图片生成、平台实现使用环境中可用的对应工具，不要求安装特定技能才能工作。交互含义变化应同步文案，但不借此改写未授权剧情。

按实际任务交付页面/状态图、关键布局及交互约定，或代码、路径验证和实际截图。对外发布需有用户授权。公开案例只包含获准的材料，项目素材和存档不因技能开源而自动获得相同许可。

保留有效设计。发现具体问题时修复对应规则，不通过不断增加通用禁令、流程步骤或审美评分证明质量。
